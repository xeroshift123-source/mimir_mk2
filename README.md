# MIMIR MK2

## 현재 운영 방향 (2026-11-12)

기본 백엔드를 기존 Google Firebase로 연결했습니다. 같은 웹 앱·mimirdb 데이터베이스·Cloud Functions를 사용해 계정과 지휘관, 저장 스코어, 뱃지, 공유 덱을 재사용합니다. Netlify 빌드 설정은 netlify.toml에 있습니다. 기존 서비스·데이터·DNS는 유지하며 이번 작업에서 운영 웹 배포는 하지 않았습니다. 상세 연결 범위와 검증은 [deploy/firebase.md](deploy/firebase.md)를 확인하세요.

## 내 니케 정보

`/#/my-nikke`에서 계정 요약, 속성별 점수 표시, 니케 검색·버스트/속성/기업/무기 다중 필터·정렬, 목록/그리드 전환과 수치 가리기, 한 명당 한 행의 육성 목록과 육성·장비/오버로드·스코어 상세를 확인할 수 있습니다. 홈 메뉴와 기능 카드에서도 접근합니다. 모바일에서는 니케 선택 후 상세로 이동합니다.

로컬에서는 `http://localhost:5173`을 사용합니다. 이 주소는 기존 Firebase 인증 허용 도메인에 등록되어 있습니다. `127.0.0.1`은 허용되지 않습니다. 기본 실행에는 로컬 PostgreSQL/API 서버나 서비스 계정 키가 필요하지 않습니다. 보존한 OCI/PostgreSQL 경로는 `VITE_ACCOUNT_BACKEND=oci`를 명시한 경우에만 사용합니다.

로그인 전에는 미연동 화면을 표시합니다. 별도의 예시 보기에서만 합성 데이터 24명을 사용합니다. 실제 계정에서는 수집된 육성 정보와 저장된 점수만 사용하며, 정보가 불완전한 니케는 미수집 수를 안내하고 평가 목록에서 제외합니다. 연구실 데이터가 부족하면 협투력도 표시하지 않습니다. 점수 누락은 `—`로 유지합니다. Firebase 서버가 제공하는 기존 저장 스코어·속성별 순위와 니케별 육성 통계를 사용합니다. 표본·정책·계산 버전 조건은 기존 서버에서 검증하며, 값이 없는 순위는 만들어내지 않습니다. 상단 내 니케 옆의 내 정보 페이지에서 뱃지와 리캡을 열 수 있습니다. 리캡은 선택한 연결 계정을 기준으로 표시합니다. 뱃지는 기존 Firebase에 저장된 획득 기록을 조회하며 전시는 기존 서버 제한인 최대 4개를 적용합니다. 리캡은 수집 완료된 니케의 현재 육성 기준 카드와 PNG 저장을 지원합니다. 기존 Firebase에서 획득한 뱃지 기록은 그대로 표시합니다. 우월코드 합산 뱃지에 미미르 스코어 순위를 대신 사용하지 않습니다.

40레벨 투력은 원본 `cp_calculator.dart`와 데이터 테이블을 이식했습니다. 원본과 같이 큐브 15레벨을 가정하고 연구실·호감도·돌파·코어·스킬·장비·소장품을 반영합니다. 4부위 오버로드와 옵션 단계 데이터가 없으면 `—`로 표시합니다. 합성 예시 옵션도 원본의 유효한 옵션 단계값을 사용합니다. 우코/공격력/우공은 장비 옵션 합계 내림차순이며 동률은 저장 전투력 순입니다. 수치 가리기는 원본과 같이 목록/그리드의 초상화 전투력·정렬 수치를 숨기고 육성 정보는 유지합니다.

오른쪽 상세에는 40레벨 전투력(협투력)과 면허증 발급 버튼이 표시됩니다. 면허증은 원본의 등급 기준·초상화·발급 도장을 사용하며, 미리보기·클립보드 이미지 복사·1280×800 PNG 저장을 지원합니다. 유효한 미미르 스코어가 있으면 협투력 옆에 소수 둘째 자리까지 표시하고, 점수가 없는 경우 스코어 영역을 생략합니다. 예시 계정의 발급 이미지에는 예시 표시를 포함하고, 연결된 계정에는 실제 동기화 수치를 사용합니다.

검증: `node tests/profile-controls.test.cjs`

TypeScript + Vite 기반 홈 및 레이드 덱 빌더. 기존 MIMIR 원본은 수정하지 않았습니다.

```sh
npm install
npm run dev
npm run build
```

배포 산출물은 `dist/`에 생성됩니다. 인증·DB·동기화는 기존 Firebase에 연결되어 있습니다. 계정 추가·갱신 버튼은 실제 Cloud Functions를 호출하므로 테스트용 더미 조회와 구분합니다.

`/#/builder/solo`에서 5개 스쿼드, `/#/builder/union`에서 3개 스쿼드를 편성합니다. 기존 프로젝트의 니케 206명(임시 니케 표시 포함), 검색·능력 검색, 버스트·속성·무기·제조사·등급 필터, 후보 10명, 드래그를 통한 슬롯 교환, 실행 취소·다시 실행, 유형별 브라우저 자동 저장을 지원합니다. 모바일은 스쿼드/아카이브 이동 버튼을 제공합니다.

덱 코드는 기존 Base64URL JSON 규격을 사용합니다. 숫자 name_code와 과거 문자열 ID/배열 코드를 읽습니다. 중복·미등록 니케·잘못된 구조는 가져오기 전에 거부합니다. 코드에는 편성 및 유니온 속성만 포함되며 후보·사용자 지정 이름·솔로 약점은 브라우저에만 저장됩니다. 버스트 표시는 단계별 보유 여부이며 쿨타임이나 실제 순환 가능 여부를 검증하지 않습니다.

캐릭터 이미지는 기존 MIMIR 프로젝트의 자산을 사용합니다. Google Fonts 연결이 없으면 시스템 글꼴로 표시됩니다. OCI 배포는 수행하지 않았습니다.

상단 **이미지 캡처**에서 편성 PNG 미리보기·다운로드·클립보드 복사를 지원합니다. 원본 600px 공유 구성을 2배(가로 1200px)로 그립니다. 빈 스쿼드를 제외하고 왼쪽에 스쿼드 이름·속성저지·버쿨감과 일반 조합 태그, 오른쪽에 3:4 카드 5장을 배치합니다. 후보는 별도 패널에 최대 두 줄로 배치하며 Made with MIMIR 표기를 유지합니다. 시즌별 특수 키워드 강조는 레이드 선택 기능 연결 후 제공됩니다. 스크롤과 화면 크기에 영향받지 않으며 캡처 시점의 편성을 사용합니다. 이미지 복사를 지원하지 않거나 권한이 거부되면 PNG 저장을 안내합니다. 이미지를 불러오지 못한 경우 불완전한 이미지를 저장하지 않고 오류를 안내합니다.

카드는 원본 이미지의 중앙 cover, 속성(좌상단)·버스트(우상단) 원본 아이콘, 하단 이름과 그라디언트 구성을 유지합니다.

왼쪽 목록을 클릭하면 니케가 선택되고 오른쪽 빈칸을 클릭하면 해당 자리에 배치됩니다. 같은 니케를 다시 클릭하거나 Escape로 선택을 취소할 수 있습니다. 드래그로도 직접 배치할 수 있으며, 오른쪽 편성·후보 카드는 한 번 클릭하면 제거됩니다. 카드별 X·이동 버튼은 표시하지 않습니다.


육성 목록에는 레벨·돌파/코어, 저장 전투력, 스킬 3종, 소장품/큐브, 4부위 장비 강화, 주요 오버로드 3종과 스코어를 표시합니다. 오버로드 요약은 원본처럼 옵션 줄 수 내림차순 후 합계 내림차순입니다. 연구실은 계정 요약 하단에 표시하고 속성별 점수 막대는 동일한 길이 척도와 값에 따른 파랑→빨강 상대색을 사용합니다.

오버로드 컬러링은 인게임/원본 규칙을 유지합니다. 1–11단계는 연회색 배경·진회색 옵션명·회색 수치, 12–14단계는 같은 배경·옵션명에 파랑 수치, 15단계는 검정 배경·흰색 옵션명·파랑 수치입니다. 목록 요약과 상세 합계의 색상은 해당 옵션의 최고 단계로 결정하며, 합산 수치나 사이트 테마로 재해석하지 않습니다.

장비 상세는 4부위 옵션을 기본으로 모두 펼치고, 오버로드 합계를 맨 위에 표시합니다. 장비 이름은 원본 매핑을 사용하며 Tier 10 이상은 원본 다크 테마의 분홍색(#ff80ab), 미만은 주황색(#ffb74d)입니다.

장비 탭의 **모듈작 시뮬레이터**는 선택한 니케의 장비를 복사해 실험합니다. 원본 OverloadSimulatorProvider의 효과 가중치·슬롯 생성 확률·단계 확률을 이식했습니다. 효과/수치 변경, 모듈·기존·락키 잠금, 부위별 되돌리기(재화 미환급), 소모 재화 집계, 돌파·코어·호감도·스킬·장비 강화 변경, 협투력 및 옵션 합계 비교를 지원합니다. 원본 정보에 반영하거나 서버에 저장하지 않습니다. 현재 입력 계정은 합성 예시이며 확률은 원본 코드 기준입니다. 모든 슬롯이 잠겼거나 수치 변경 대상이 없으면 해당 변경 버튼을 비활성화합니다.

로컬 개발 서버에서는 로그인 창의 `더미 계정으로 테스트` 버튼으로 내 정보·뱃지·리캡을 확인할 수 있습니다. 합성 니케 24명과 테스트 뱃지를 사용하며 실제 계정 API에 쓰지 않습니다. 테스트 모드는 탭 sessionStorage에 유지되고 로그아웃으로 종료됩니다. 프로덕션 빌드에는 테스트 진입 버튼과 fixture 모듈이 포함되지 않습니다.
